Hoot Unfathomably Changelog
===========================

Version 0.4.5
-------------

- Preview a selected server's public color scheme on the login screen without
  creating an account, persisting a profile, or sending credentials.

Version 0.4.4
-------------

- Change the mixed-purpose bottom navigation destination from a settings gear
  to a More ellipsis, with app settings remaining a distinct action inside it.
- Load the selected Pleroma FE theme preset on Pleroma and Akkoma hosts that do
  not publish Soapbox colors, with bounded parsing and safe theme-name checks.
- Add explicit Mastodon 4.6 and Akkoma fixtures to the strict compatibility
  suite while preserving capability-degraded Rebased and Pleroma coverage.
- Identify the selected server correctly in the host picker instead of labeling
  every Mastodon-compatible server as Unfathomably.
- Publish Mastodon 4.5 and newer quote posts with `quoted_status_id`, retain the
  `quote_id` contract on Unfathomably, Rebased, Pleroma, and Akkoma, and render
  each family's returned quote shape.
- Use unified query-style WebSocket streams on Rebased, Pleroma, and Akkoma,
  including their plural `user:notifications` stream, while retaining current
  path-style streams on Unfathomably and Mastodon.
- Add a public, read-only compatibility probe covering established Soapbox,
  Rebased, Pleroma, Akkoma, Mastodon, and Unfathomably servers without
  registering applications or changing server state.

Version 0.4.1
-------------

- Add foreground WebSocket updates for the home timeline, own-post feed,
  notifications, followed groups, individual group discussions, followed
  Sources, and individual Sources.
- Use the new Unfathomably aggregate `user:groups` and `user:sources` streams
  instead of approximating either feed from unrelated public activity.
- Honor Mastodon v2 and v1 advertised streaming origins and authenticate with
  the WebSocket subprotocol so access tokens never appear in stream URLs.
- Handle live status additions, edits, deletions, and notifications with
  bounded protocol parsing and defensive response validation.
- Close sockets while the app is backgrounded, recover with exponential
  backoff and jitter, and perform REST catch-up after focus or network gaps.
- Preserve scheduled REST notification polling in the Android background and
  clean REST degradation on older Rebased and Pleroma servers.

Version 0.4.0
-------------

- Add a complete own-account book library with four standard shelves, title,
  author, and ISBN search, quiet shelf moves and removal, plus page or percent
  reading progress.
- Keep timeline publication separate from shelf management with dedicated
  review, comment, and quotation forms, ratings, page references, content
  warnings, and visibility controls.
- Add foreground-only Android GPS path recording with accuracy and plausible
  speed filtering, stop and resume track segments, live local previews,
  distance, duration, and elevation metrics.
- Add bounded GPX import and export, account-scoped unfinished draft recovery,
  explicit precise-location confirmation, standard media upload, and native
  route publication.
- Add Books and GPS paths entry points to Worlds, native resource cards,
  structured status context, Options, and deep-link routing.
- Document location and book-library privacy boundaries and preserve clear
  feature-unavailable behavior on older Rebased and Pleroma servers.
- Add contract tests for shelf normalization and mutation, native book
  activity, GPS filtering, segmented GPX round trips, route upload and
  publication, local draft recovery, deep links, and degraded servers.

Version 0.3.0
-------------

- Add first-class browsing, timelines, bounded discovery, local resolution,
  structured facts, bridge provenance, and original-resource links for all 16
  Unfathomably 3.5 Worlds families.
- Add followed Sources timelines, source lists, discovery, detail, preview,
  follow, and unfollow support for publications, channels, feed actors, RSS,
  and Atom sources.
- Update groups to the current search, discovery, detail, relationship,
  permission, moderation, federation-policy, membership, and timeline
  contracts, with narrow fallbacks for older Rebased servers.
- Add status polls and poll composition, content warnings, sensitive-media
  flags, visibility controls, event details, and explicit event participation.
- Present native status facts and Nostr, AT Protocol, or diaspora* bridge
  provenance without obscuring ordinary discussions and reactions.
- Extend notifications for current group, emoji, poll, event, participation,
  move, edit, and follow event types while retaining the compatible v1 polling
  boundary.
- Add guarded, explicit audio and video playback. Broken federated image
  previews now retry the proxy original and remote original before collapsing
  to a compact unavailable state, and full-screen viewing uses the same safe
  fallback chain.
- Update Expo 57 dependencies to their compatible patch releases, add the
  missing Worklets Metro peer, and harden the release gate around current
  production dependency advisories.
- Validate the release against unfathomably-be 3.5.0, the paired August 12,
  2026 frontend source, capability-degraded Rebased and Pleroma fixtures, and
  an attached Android device.

- Show rich, tappable link previews using the preview-card metadata supplied by
  Unfathomably, Rebased, and Pleroma status responses.
- Keep external links usable when an older server omits preview-card metadata,
  without treating account mentions or hashtags as page previews.
- Keep preview images contained within their cards and hide failed images while
  retaining the title, description, provider, and link action.
- Keep a bounded, tappable attachment preview on compact ancestor posts in a
  discussion instead of reducing remote images and GIFs to filename text.
- Collapse large leading reply-recipient lists into the existing reply-context
  row, including a concise count of the other participants.

Version 0.2.9
-------------

- Load large discussions through bounded ancestor and descendant pages instead
  of requesting an entire thread at once.
- Initially show up to 10 earlier posts and 20 replies, with explicit controls
  to load additional posts only when another page exists.
- Preserve the legacy context endpoint as a degraded fallback for older
  Rebased and Pleroma servers that do not implement paged discussions.
- Avoid repeating an expensive unbounded request after a paged request times
  out or receives a gateway error, and replace HTML proxy errors with a clear
  status message.
- Add backend and mobile regression coverage for pagination cursors, bounded
  windows, incremental loading, compatibility fallback, and 502 handling.

Version 0.2.8
-------------

- Stop and unregister background notification polling when Android blocks
  notification delivery, avoiding repeated headless JavaScript wakeups that
  cannot produce a visible alert.
- Restore polling automatically on a later app launch when the user preference
  remains enabled and Android notification delivery is allowed again.
- Record permission-denied background wakes without loading account data or
  contacting the server.
- Added regression coverage for startup restoration and background-task
  permission revocation.

Version 0.2.7
-------------

- Fixed a community destination carrying into a later ordinary reply when the
  reusable composer tab remained mounted.
- Give every reply, quote, group post, and direct post a complete unique
  compose intent so unrelated destinations and drafts cannot bleed between
  modes.
- Clear compose routing after successful publication and ignore late parent
  lookups after the compose target changes.
- Added regression coverage for community-to-reply transitions, fresh direct
  posts, request payload omission, and target-loading races.

Version 0.2.6
-------------

- Preserve baseline login, timelines, discussions, replies, reposts,
  favourites, notifications, and profiles for capability-degraded Rebased and
  Pleroma servers.
- Detect quote reposts, emoji reactions, and thumbs-down support from status
  response fields and hide only the unavailable extension controls.
- Normalize unsupported group and reaction endpoints into clear degraded
  states instead of displaying raw server errors.
- Require degraded Rebased and Pleroma fixtures in the strict release gate.

Version 0.2.5
-------------

- Mark replies in every feed with a tappable parent-context row.
- Show the replied-to account using Pleroma/Rebased metadata or the standard
  Mastodon mentions list, with a clear conversation fallback when the server
  omits the account handle.

Version 0.2.4
-------------

- Fixed notification discussions being replaced by a fetch-canceled error when
  a server returns an exceptionally large unpaginated status context.
- Load the selected status independently, keep context timeout and retry state
  non-blocking, and virtualize a bounded set of nearby discussion statuses.
- Fixed reply, quote repost, and group-compose navigation from root discussion
  screens.
- Use the server favourite and dislike actions for thumbs up and thumbs down,
  and show actionable errors when repost or reaction requests fail.

Version 0.2.3
-------------

- Added a one-time Android notification onboarding prompt after the first
  account becomes active, using the same permission, baseline, and background
  task checks as the Settings toggle.
- Rebuilt the release test suite around explicit Unfathomably, Rebased, and
  Pleroma contracts for timelines, groups, discussions, reactions, accounts,
  OAuth, notifications, and persisted sessions.
- Removed retired server-version test matrices and added a strict,
  self-tested release check that prevents obsolete service imports and API
  routes from returning.
- Removed retired screens and conditional legacy tabs from the active
  navigation tree so the tested app surface matches the six current feeds,
  groups, posting, notifications, and options destinations.

Version 0.2.2
-------------

- Made FBXL Social an explicitly optional login shortcut and added validated
  custom server entry for Unfathomably, Pleroma, Rebased, and
  Mastodon-compatible hosts.
- Added browser-based OAuth authorization-code login on the selected server
  while retaining direct password login for servers that support it.
- Made account creation and password recovery open the currently selected
  server instead of using legacy Lotide or FBXL-specific routes.
- Restored the host-picker suite to the release gate and covered custom hosts,
  local development ports, saved-server isolation, OAuth callback validation,
  and unavailable-host behavior.

Version 0.2.1
-------------

- Fixed Android login failing after successful authentication because the
  generated Secure Store token key contained characters rejected by the native
  module.
- Added native-compatible Secure Store key validation to the test environment
  and restored the current Unfathomably login suite to the release test run.
- Kept server-handled registration from leaving the login form permanently
  disabled.
- Replaced the inherited Lotide notification poller with the
  Mastodon-compatible Unfathomably notifications endpoint.
- Migrated background notification settings to Hoot Unfathomably task,
  storage, and Android channel identifiers without alerting old history.
- Updated notification taps to open Unfathomably status discussions and
  removed stale Lotide labels and errors from notification settings.

Version 0.2.0
-------------

Initial public Hoot Unfathomably release.

- Reoriented the former Hoot Mobile client around the Unfathomably
  Mastodon-compatible API and its group extensions.
- Added Home, followed Group feed, Groups, New post, Notifications, and
  Options navigation.
- Added group discovery, membership, group timelines, and group posting.
- Added account timelines, threaded status views, replies, reposts, quote
  reposts, and server-supported emoji, positive, and negative reactions.
- Added notification loading and navigation to the relevant discussion.
- Added an accessible full-screen image viewer with zoom and pan support for
  long or text-heavy images.
- Stored authentication tokens in the platform secure store, migrated legacy
  local tokens safely, and require HTTPS for remote servers.
- Updated the mobile stack to Expo SDK 57, React 19, and React Native 0.86.
- Added strict static checks, unit tests, Expo diagnostics, production
  dependency auditing, Android release builds, and Android device smoke tests.

The previous Lotide-focused changelog was intentionally retired with this
project's public rename. This file records Hoot Unfathomably releases only.
